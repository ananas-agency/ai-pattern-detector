# ai-pattern-detector v1.7.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship ai-pattern-detector 1.7.0: rewrites that never invent facts and check themselves, a catalog recalibrated to Wikipedia's October 2026 changes, ~17 new patterns with a default strength on every pattern, safety guards, a fiction register with a narrative checklist, and repo hygiene (validator, CI, marketplace install, issue templates, eval set).

**Architecture:** The skill is Markdown instructions: `SKILL.md` (workflow) plus `references/patterns.md` (always loaded), `references/examples.md` (rewrite phase only), and a new `references/fiction.md` (fiction register only). Mechanical rules (version sync, section numbering and references, word budget, strength tags, example hygiene, README score math) are enforced by a new stdlib-only Python validator with unit tests. Behavior is tested by 20 hand-run eval cases in `evals/`: each content task writes its cases first, then changes the skill, then runs its cases by dispatching a fresh subagent that follows the repo's `SKILL.md`.

**Tech Stack:** Markdown, Python 3 standard library (`unittest`), GitHub Actions, Claude Code CLI 2.1.263 (`claude plugin validate`, `claude plugin marketplace`).

**Spec:** `docs/superpowers/specs/2026-10-28-v1.7-safe-rewrites-and-fiction-design.md`. Read it before starting; tasks cite its parts (e.g. "spec 3a") instead of repeating them.

## Global Constraints

- **Version:** `plugin.json` `version` becomes exactly `1.7.0`. CHANGELOG headings use three parts from now on: `## 1.7.0 — 2026-MM-DD` (the date the release is finished). Older headings stay as written.
- **Score formula unchanged:** `score = min(100, Strong × 12 + Medium × 5 + Weak × 2)`. Bands unchanged: 0–20 reads human · 21–40 mostly human (minor tells) · 41–65 AI-assisted feel · 66–100 strong AI signature.
- **Word budget:** `SKILL.md` + `references/patterns.md` combined ≤ **9,000 words** (counted as whitespace-separated tokens). `examples.md` and `fiction.md` are outside the budget. Don't raise it; the fallback order is in Task 8.
- **Categories become 12.** All spec Part 3 patterns fold into §1–§11; §12 is narrative tells, fiction register only.
- **Eight registers, named exactly:** Social post · Marketing / landing page · Product description / e-commerce · Blog / editorial / newsletter · Scientific / academic · Business / professional · Fiction / narrative · General.
- **Example-heading register labels** (what `examples.md` headings end with, and what the validator accepts): `social post`, `marketing / landing page`, `product description`, `blog / editorial`, `scientific / academic`, `business / professional`, `fiction / narrative`, `general`.
- **Strength tags:** `[Strong]`, `[Medium]`, `[Weak]`, or a compound starting with one of those words (`[Medium; Strong at 3+]`, `[Weak alone; Medium when it reframes]`). Validator regex: `\[(Strong|Medium|Weak)\b[^\]]*\]`.
- **Never invent facts** in any rewrite, example, or README sample, except the fiction exception (spec 7e).
- **Don't name the compared skill** anywhere in shipped files, eval texts, this repo's docs, or commit messages. Write all pattern descriptions and example sentences fresh; never copy its text. Short generic watch phrases and Wikipedia examples are fine.
- **`plugin.json` `description` stays exactly as it is.** The output format keeps every current section in the same order; v1.7 only adds lines.
- **Branch:** `feature/v1.7-safe-rewrites-and-fiction` (checked out; spec committed). **Never push.** The user pushes.
- **Commit after every task.** Trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Files are UTF-8 with CRLF in this Windows checkout** (`core.autocrlf=true`, `.gitattributes` `* text=auto`). Anything that reads them must decode UTF-8 explicitly and normalize line endings.

### How to run an eval case (used by every task; Task 1 writes it into `evals/README.md`)

1. For a request that writes to a file (case 08), copy the case file to the scratchpad first and use the copy's path.
2. Dispatch a fresh general-purpose subagent with this prompt, filling the `<>` parts:
   > You are testing a Claude skill from its source files. Do not use the Skill tool: the installed copy is an older version. Read `<repo>/skills/ai-pattern-detector/SKILL.md` and follow it exactly, as if it were loaded as a skill, including reading the reference files it tells you to read. Then carry out this request on the text in `<repo>/evals/cases/<file>` (or the copy at `<path>`): "<request from the table>". Output exactly what the skill would output to the user, and nothing else.
3. Compare the output with the case's expected-behavior row. Record PASS or FAIL with a one-line reason in the task notes (Task 11 writes `evals/RESULTS.md`).
4. On FAIL, fix the skill text (not the case), then re-run that case.
